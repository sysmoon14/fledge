Security

The thermostat and Home Assistant talk over your MQTT broker. Whoever can publish to it can do what the thermostat can.

What the thermostat may do

Only to the devices you chose in the integration, and only:

  • switch a light, switch or fan on or off;
  • set a light's brightness, warmth or colour;
  • set a thermostat's temperature;
  • set a speaker's volume, and play or pause it;
  • run a scene, script or button;
  • take a camera's picture;
  • arm or disarm an alarm panel, with its code.

Anything else it asks for is refused and logged. A notification's answer only fires an event, for your automations. Think before adding a card that opens something, a garage door for instance: anyone at the thermostat, or anyone who can publish to your broker, can use it.

The broker

  • Give the broker passwords, and TLS if you can (the app takes a CA certificate).
  • If it supports ACLs, let only Home Assistant publish to nestlocal/+/set/#, and only the thermostat's user publish to nestlocal/+/ui/#.

Google's cloud

Block cloud in Set up (--block-cloud) points Nest's and Google's servers at nowhere on the thermostat. It needs no internet access, only your Wi-Fi.

SSH

SSH is off unless you turn it on. Set up can create a key for you, and keeps password login off unless you allow it (--ssh-key-only on the command line).

Updates

The thermostat installs only releases signed with Fledge's release key, and checks each download's digest. See Updates.

Matter

Matter uses the test vendor ID (0xFFF1) and test attestation, so controllers treat the thermostat as uncertified.
